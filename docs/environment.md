# Environment and sandbox credentials

All backend/native worker variables live in the repository-root `.env`. FastAPI receives the same `INTERNAL_SERVICE_TOKEN` via `uv --env-file ../../.env` or Compose. Next.js reads only the public API URL through `next.config.ts`; no private keys are exported into browser code. `.env`, `.env.test` and runtime secrets are ignored by Git and packaging. `.env.example`, `.env.staging.example` and `.env.production.example` are safe templates only.

| Variables | Required / source | Where / verification |
|---|---|---|
| DATABASE_URL, POSTGRES_PASSWORD | Required; generated locally by setup-local | Root .env; migrate then `/ready`; Compose rewrites the host to postgres internally. |
| REDIS_URL | Required; local Redis, no paid account | Root .env; `/ready`, admin System health and worker heartbeat. |
| JWT_ACCESS_SECRET, JWT_REFRESH_SECRET | Required; independent random values generated by setup | Root .env; restart API, sign in, test rotation; changing secrets invalidates existing sessions. |
| INTERNAL_SERVICE_TOKEN, PYTHON_SERVICE_URL | Required; token generated locally | Root .env and FastAPI process; `/health` then an authenticated recommendation or checkout request. |
| PAYMENT_PROVIDER=local, PAYMENT_WEBHOOK_SECRET | Works without any third-party keys; secret generated locally | Root .env; customer sandbox payment and signed callback integration tests. |
| SHIPPING_PROVIDER=local, SHIPPING_WEBHOOK_SECRET | Local simulator; no external keys | Root .env; warehouse shipment controls and signed shipping callback tests. No actual carrier is integrated. |
| EMAIL_PROVIDER=smtp, SMTP_HOST, SMTP_PORT | Local Mailpit capture, no external key | Root .env; restart worker; inspect http://localhost:8025. External email delivery is intentionally disabled. |
| S3_ENDPOINT, S3_PUBLIC_URL, S3_BUCKET, S3_ACCESS_KEY_ID, S3_SECRET_ACCESS_KEY | Local MinIO; setup generates credentials, no paid account | Root .env; upload an image from Seller Products; download returned WebP URL; MinIO console uses these local credentials. |
| FRONTEND_URL, NEXT_PUBLIC_API_URL | Required URLs; no secret | Root .env; exact browser Origin/CORS must match. Rebuild Next.js after changing its public URL. |
| DEMO_MODE, DEMO_PASSWORD | Local-only synthetic accounts and simulators | Root .env; seed once. Production must use DEMO_MODE=false. Never expose the local seed accounts publicly. |
| STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET | Optional; genuine Stripe **test-mode** credentials from [Stripe API keys](https://docs.stripe.com/keys) and [webhook setup](https://docs.stripe.com/webhooks) | Root .env only; use sk_test_ key, select PAYMENT_PROVIDER=stripe, restart API/worker. Stripe CLI can forward to `/api/v1/webhooks/stripe`. The adapter rejects live secret keys. |
| NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY | Optional test publishable key | Safe to expose only a Stripe test publishable key. The current UI demonstrates the local simulator; a production-like Stripe Elements checkout UI is not included. The REST intent adapter returns a test client secret for separate sandbox validation. |
| SHIPPING_API_KEY, EMAIL_API_KEY | Reserved optional provider placeholders | No external carrier/email adapter is claimed. The application works entirely locally without them. |

After updating root `.env`, restart the relevant native processes or run `docker compose --profile app up -d --force-recreate api worker python`. Rebuild the frontend if a NEXT_PUBLIC variable changes. Restart MinIO after changing root object-storage credentials; changing credentials does not migrate existing clients automatically. Run `/ready`, the signed-event integration tests, a seller upload, and inspect Mailpit. Never paste secrets into README files, screenshots, issue bodies, or shell commands that will be captured as evidence.

No paid AI API is required. Pricing, feeds and all recommendation modes use deterministic code. Stripe test execution, public HTTPS hosting, external email/storage accounts and real shipping providers are not automatically verified by local simulator tests. A supported S3-compatible deployment can use the same SDK adapter with a dedicated least-privilege bucket and an HTTPS public asset endpoint; external bucket policy and credentials must be configured by its owner.
